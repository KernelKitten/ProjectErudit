# Project Erudit

Приложение для записи на дополнительные занятия в гимназии «Эрудит».

Учитель отмечает в календаре время для дополнительных занятий. Ученики записываются на них сами, или учитель записывает их сам. Приложение напоминает о занятиях через мессенджер MAX и считает, с кем, сколько раз и сколько часов занимался учитель.

Школьный проект. Автор: KernelKitten.

## Статус

**Этап 3 завершён: справочники и импорт.** Справочники школы, производственный календарь (загрузка с GitHub по расписанию), классы, учителя и ученики с родителями (загрузка из Excel и ручная правка), журнал изменений, проверка данных, перевод школы на новый учебный год с напоминаниями в MAX. До этого: вход по QR-коду и из мини-приложения MAX, роли с переключением.

## Возможности (планируются)

- **Календарь** в привычном школе виде: строки — дни недели, столбцы — уроки. Нерабочие дни из производственного календаря РФ, подсветка каникул.
- **Слоты и регулярные занятия**: одно действие — занятия на всю четверть, нерабочие дни пропускаются автоматически. Изменение «только этого» или «этого и всех последующих» занятий.
- **Запись**: ученик записывается сам или его записывает учитель; ученик может отказаться.
- **Посещаемость**: отметка «проведено» и присутствия каждого ученика.
- **Вход и уведомления через MAX**: регистрация по номеру телефона, вход на ноутбуке по QR-коду, напоминания и кнопки прямо в сообщениях бота.
- **Отчёты** в академических часах (40 минут) для учителя, классного руководителя и завуча с выгрузкой в Excel; закрытие периода и журнал изменений.
- **Для всей школы** (1–11 классы), включая короткие занятия до первого урока в начальной школе.
- **Роли**: учитель, ученик, классный руководитель, завуч, администратор, родитель.

## Технологии

- C#, .NET 10
- Blazor (Interactive Server) + MudBlazor
- PostgreSQL + Entity Framework Core
- Hangfire — фоновые задачи (напоминания, загрузка календаря); панель `/hangfire` для администратора
- ClosedXML — импорт и экспорт Excel
- MAX — бот и мини-приложение
- xUnit — тесты

## Структура решения

```
Erudit.slnx
├── src/
│   ├── Erudit.Domain          — сущности и правила, без зависимостей от базы и UI
│   ├── Erudit.Infrastructure  — PostgreSQL, MAX API, Hangfire, Excel, внешние данные
│   └── Erudit.Web             — Blazor-интерфейс, вход (запускаемый проект)
└── tests/
    └── Erudit.Tests           — автоматические тесты
```

Зависимости: `Web → Infrastructure → Domain`, `Web → Domain`, `Tests → Domain, Infrastructure`. `Domain` не зависит ни от чего.

## Запуск

Нужно: .NET SDK 10 (версия зафиксирована в `global.json`), Visual Studio 2026 или `dotnet` CLI, доступ к PostgreSQL.

1. Строка подключения к базе и токен бота MAX хранятся в **User Secrets** (на компьютере разработчика, не в git):
   ```
   dotnet user-secrets set "ConnectionStrings:Erudit" "Host=...;Port=5432;Database=erudit_dev;Username=...;Password=..." --project src/Erudit.Web
   dotnet user-secrets set "Max:BotToken" "токен тестового бота" --project src/Erudit.Web
   ```
   При разработке работает **тестовый бот** `@id231107791231_1_bot` (имя — в `appsettings.Development.json`), основной бот — на [тестовом стенде](#тестовый-стенд).
   В режиме разработки бот получает сообщения через long polling (`Max:UseLongPolling` в `appsettings.Development.json`) — туннель не нужен. Важно: если бот запущен на двух компьютерах одновременно, они будут «отбирать» друг у друга события.
2. Запуск сайта: в Visual Studio — открыть `Erudit.slnx` и нажать F5; или из командной строки:
   ```
   dotnet run --project src/Erudit.Web
   ```
   Сайт откроется на http://localhost:5067 (https://localhost:7284).
3. Создать или обновить таблицы в базе (миграции EF Core; `dotnet-ef` ставится как локальный инструмент):
   ```
   dotnet tool restore
   dotnet ef database update --project src/Erudit.Infrastructure --startup-project src/Erudit.Web
   ```
   При первом запуске в режиме разработки пустая база заполняется выдуманными тестовыми данными (`SeedDevData` в `appsettings.Development.json`).

   Войти без MAX можно на странице http://localhost:5067/dev/login (только в режиме разработки): выбрать любого человека из тестовых данных. Чтобы проверять вход через MAX на себе, укажите свой номер — его получит тестовый администратор:
   ```
   dotnet user-secrets set "Dev:MyPhone" "+79XXXXXXXXX" --project src/Erudit.Web
   ```
   Номер можно отдать и любому другому человеку из тестовых данных («Фамилия Имя», как на странице `/dev/login`):
   ```
   dotnet user-secrets set "Dev:Phones:Андреев Матвей" "+79XXXXXXXXX" --project src/Erudit.Web
   ```
   Мини-приложению MAX нужен публичный HTTPS-адрес — его проверяем на [тестовом стенде](#тестовый-стенд).
4. Тесты:
   ```
   dotnet test
   ```
   Тесты с базой данных используют отдельную базу (она пересоздаётся при каждом запуске). Строка подключения — в User Secrets тестового проекта, без неё эти тесты пропускаются:
   ```
   dotnet user-secrets set "ConnectionStrings:EruditTest" "Host=...;Database=erudit_test;Username=...;Password=..." --project tests/Erudit.Tests
   ```

## Тестовый стенд

https://erudit.23mx.ru — для проверки мини-приложения MAX и показа руководителю. Тестовые (выдуманные) данные, вход только через MAX (входа разработчика `/dev/login` там нет).

- Контейнер LXC (Ubuntu 22.04) на домашнем Proxmox, сайт — служба `erudit` (systemd) на порту 5000, снаружи — существующий nginx с HTTPS ([deploy/nginx-erudit.conf](deploy/nginx-erudit.conf)).
- Окружение `Demo` (`appsettings.Demo.json`): база `erudit_demo`, схема обновляется сама при запуске, пустая база заполняется тестовыми данными.
- Секреты — в файле `/etc/erudit/erudit.env` на сервере (`ConnectionStrings__Erudit=...`, `Max__BotToken=...`, `Dev__MyPhone=...`).
- Сертификат API MAX выдан корневым центром Минцифры (Russian Trusted Root CA), которого нет в стандартных списках Windows и Linux. Приложение доверяет ему только в запросах к MAX (`MaxCertificateTrust`), настраивать систему не нужно.
- На стенде работает основной бот; на компьютере разработчика — второй, тестовый бот (свой токен в User Secrets), иначе они отбирают друг у друга события.

Публикация (нужен SSH-ключ и имя `erudit-demo` в `~/.ssh/config`):
```
.\deploy\deploy.ps1
```
Скрипт собирает сайт под Linux, копирует на сервер в новую папку `/opt/erudit/releases/<дата-время>`, переключает на неё ссылку `/opt/erudit/app` и перезапускает службу. Первая настройка сервера — `.\deploy\deploy.ps1 -Setup`. Журнал сайта: `ssh erudit-demo journalctl -u erudit -f`.
