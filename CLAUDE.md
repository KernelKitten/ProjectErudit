# Project Erudit

Школьный проект: приложение для записи на дополнительные занятия. Учитель отмечает в календаре свободные слоты, ученики на них записываются (или учитель назначает ученика сам).

- **README.md поддерживать в актуальном состоянии**: при каждом заметном изменении (новый этап, новый проект в решении, изменился способ запуска) обновлять его в том же коммите.

- Требования собраны (см. ниже и `docs/`). Работаем по этапам из `PLAN.md`; перед каждым этапом обсуждаем, что и как делаем. Этап 0 закрыт (Dev Tunnel отложен до этапа 2). Этап 1 закрыт: модель данных, миграции, тестовые данные. ## Принятые решения

### Стек (предварительно, окончательно — после разговора со школьным IT)
- Blazor (Server или смешанный режим — обсуждается), PostgreSQL, C#, Visual Studio.
- Авторизация и уведомления через мессенджер MAX (бизнес-аккаунт уже есть): мини-приложение + бот.

### Масштаб
- До 50 учителей и до 1000 учеников, одна школа.
- Приложение для всей школы: начальная (1–4), средняя и старшая (5–11). Пятидневка.
- Учителя работают в основном с ноутбуков; ученики, скорее всего, с телефонов (мобильный вид — проверять на практике).

### Роли
- Учитель (основная роль: изначально приложение для учителей; ученики — дополнение).
- Ученик.
- Администратор.
- Завуч / руководитель — видит отчёты по всем.
- Классный руководитель — может вести несколько классов, видит всё о своих учениках. У него есть телефоны детей и родителей.
- Родитель — желательно. Привязка «родитель ↔ ученик» — через одноразовый код, который выдаёт классный руководитель (ученик в подтверждении не участвует). Если IT даст связи из школьной базы — импорт.
- У одного человека может быть несколько ролей.

### Школьное расписание (rasp.erudit23.ru) — возможный источник данных
- Сайт гимназии «Эрудит» сам грузит данные из JSON (неофициальный API, без документации — нужно разрешение школьного IT, admin@erudit23.ru):
  - `https://rasp.erudit23.ru/json/readJsonRaspForAll.php` (~850 КБ): `raspByKlass`, `raspByTeacher`, `raspByClassrooms`, `hoursByTeacher`, `teachersArray`, `teachersFullArray`, `classroomsArray`, `klassTeachers` (класс → ФИО классного руководителя), `subjectsLong`.
  - `https://rasp.erudit23.ru/json/readJsonRaspByKlass.php?ts=<метка>` — с параметром `ts` отвечает `{"cached":true}`, если расписание не менялось (удобно для периодической проверки).
  - Запись урока: `klassStr`, `dayN` (0 = Пн), `urokN` (0 = 1-й урок), `subjectStr`, `groupStr`, `teacherStr` (Фамилия И.О.), `classroomStr`; в `raspByTeacher` ещё `ringStart`/`ringEnd`.
- `teachersArray[i]` (Фамилия И.О.) и `teachersFullArray[i]` (полное ФИО) — параллельные массивы: так сопоставляем краткое имя на сайте с полным ФИО учителя у нас. Краткое имя храним в карточке учителя как внешний ключ; однофамильцев и спорные случаи администратор сопоставляет вручную.
- `raspByTeacher["Фамилия И.О."][день][урок]` — список уроков учителя; пустой список = учитель свободен. Ссылка вида `https://rasp.erudit23.ru/#%D0%9A...` — это то же краткое имя в URL-кодировке (UTF-8, в C# `Uri.UnescapeDataString`).
- Применение: импорт учителей, классов, классных руководителей, предметов, кабинетов, звонков; предупреждение о конфликтах (у класса урок, кабинет занят). Учеников там нет.
- **Окна учителя** (решено делать, если IT разрешит): в сетке создания слотов показывать уроки учителя серым, окна подсвечивать; кнопка «предложить слоты» заполняет черновик по окнам (и урокам после последнего урока), учитель отмечает нужные и сохраняет.
- Формат может измениться без предупреждения → отдельный адаптер в `Infrastructure`, ошибки разбора не должны ломать приложение.

### Регистрация и пользователи
- Основной способ: пользователь делится телефоном через `requestContact()` в MAX, сервер ищет номер в загруженных списках и привязывает аккаунт MAX к ученику / родителю / учителю. Одноразовый код от классного руководителя — запасной вариант.
- Списки загружаются из Excel по шаблону (шаблон можно скачать в приложении). Всю школу загружает администратор / завуч, свой класс — классный руководитель.
- Классный руководитель может править карточки своих учеников вручную.
- Ученик без MAX: классный руководитель добавляет его в список класса, учитель записывает на занятие вручную; уведомлений он не получает.

### Интерфейс и вход
- Один сайт, два входа: в браузере — по QR-коду / ссылке через бота (одноразовый токен, подтверждение кнопкой в боте); в мини-приложении MAX (это тот же сайт) — автоматически по `initData`.
- Учителя/завуч/админ работают в основном в браузере на ноутбуке, ученики/родители — в мини-приложении. Страницы адаптивные.
- Телефон нужен один раз при регистрации (связать MAX id с человеком в базе); дальше опознаём по MAX id.
- **Проверено 2026-10-17:** ссылка `https://max.ru/id231107791231_bot?start=<payload>` присылает боту `bot_started` с полем `payload` — и для нового пользователя, и для уже открытого диалога (два разных телефона). Вход по QR через бота реализуем.
- UI-библиотека: MudBlazor (предварительно).
- Один бот на всех: `@id231107791231_bot` (создан 2026-10-17). Ссылки: `https://max.ru/id231107791231_bot`, мини-приложение — `...?startapp`. Токен — только в User Secrets.

### Модель данных (этап 1, согласовано 2026-10-17)
- Код сущностей — `Erudit.Domain` (папки `People`, `School`, `Calendar`, `Lessons`, `Accounting`); маппинг в таблицы — `Erudit.Infrastructure/Persistence/Configurations`; миграции — `Erudit.Infrastructure/Persistence/Migrations`.
- Миграции: `dotnet ef migrations add <Имя> --project src/Erudit.Infrastructure --startup-project src/Erudit.Web --output-dir Persistence/Migrations`, применить — `dotnet ef database update --project src/Erudit.Infrastructure --startup-project src/Erudit.Web` (`dotnet-ef` — локальный инструмент, `dotnet tool restore`).
- Одна таблица `Person` для всех людей, роли — `PersonRole` (Admin, HeadTeacher, Teacher, Student, Parent). Классный руководитель — не роль, а `SchoolClass.ClassTeacherId` (может вести несколько классов).
- Один человек — один телефон (`Phone`, формат +79991234567, уникальный); `MaxUserId` уникальный.
- Классы привязаны к учебному году (`AcademicYear`); состав — `ClassMembership` с датами `FromDate`/`ToDate`: перевод 7а → 7б закрывает старую запись и открывает новую. В каждый момент у ученика ровно один класс (уникальный индекс по «открытой» записи).
- Серия: один день недели, каждую неделю (вторник и четверг — две серии). `SeriesPlanner` генерирует занятия, пропуская нерабочие дни.
- Запись на всю серию — `SeriesEnrollment`: создаёт записи на все будущие занятия серии (и на добавленные позже); отказаться можно от отдельного занятия.
- Занятие: `StartsAt` (UTC, `timestamptz`) + `DurationMinutes`; `ActualDurationMinutes` — если учитель поправил; `Status`: Planned / Held / NotHeld / Cancelled.
- Запись (`Enrollment`): уникальна по (занятие, ученик); `Status` Active / Declined / Removed; `Source` Self / Teacher / Parent / Series; `Attendance` Unknown / Present / Absent.
- Параллели 0–11: 0 — подготовительная группа перед 1-м классом (на всякий случай, пока не используется).
- Каникулы (`Vacation`) могут ограничиваться параллелями (`GradeFrom`/`GradeTo`), например только 1-е классы; без ограничений — для всех, включая 0.
- Производственный календарь в БД — только исключения (`CalendarDay`); остальные дни: Пн–Пт рабочие. `IsManual` — правка администратора, автозагрузка её не трогает.
- Ничего не удаляем физически (`IsActive`, статусы); каскадное удаление запрещено везде, кроме `PersonRole`.
- **Тестовые данные**: `Erudit.Infrastructure/Persistence/Seed/DevDataSeeder.cs` — выдуманные люди (телефоны `+7000XXXXXXX`), год 2026/27, звонки 0–9 (время 8–9 урока — предположение), 10 предметов, 7 кабинетов, 8 учителей (Зайцев — админ, Белова — завуч), 12 классов по 10 учеников, родители (у 1–4 классов `NotifyAll`), перевод 7а → 7б с 01.10, 6 серий до 25.12 и разовые занятия, сентябрь закрыт. Случайность с фиксированным зерном. Заполняет только пустую базу; при старте в Development, если `SeedDevData: true` (`appsettings.Development.json`).
- **Тесты с базой**: отдельная база `erudit_test` (пересоздаётся при каждом запуске тестов с ICU `ru-RU`, миграции + seed, «сейчас» = 2026-10-17 12:00 UTC). Строка подключения — User Secrets тестового проекта `ConnectionStrings:EruditTest`; без неё тесты с атрибутом `[DatabaseFact]` пропускаются. Не запускать два прогона тестов одновременно — они пересоздают одну базу.
- Enum в БД хранятся строками; имена таблиц и колонок — snake_case (`EFCore.NamingConventions`); id — `int` (у журнала — `long`).

### Вход и роли (этап 2, согласовано 2026-10-17)
- Cookie Authentication (`erudit.auth`): на 30 дней со скользящим продлением; галочка «Чужой компьютер» → до закрытия браузера. Кнопка «Выйти» → снова вход по QR.
- Cookie ставится только HTTP-адресами `/auth/*` (`Erudit.Web/Auth/AuthEndpoints.cs`), не через SignalR. Формы на страницах — обычный `<form method="post">` с `<AntiforgeryToken />`.
- `SignInService` — единая точка входа для всех способов (разработчик, QR, мини-приложение).
- Роли в интерфейсе (`AppRoles`): Teacher, ClassTeacher (вычисляется: ведёт класс в текущем учебном году), HeadTeacher, Admin, Parent, Student. В cookie одна **активная** роль (`ClaimTypes.Role`, по ней `[Authorize(Roles = ...)]`) и список доступных (`erudit:available_role`). Переключение роли — в меню пользователя (POST `/auth/switch-role`); меню слева показывает разделы только активной роли. При входе активна первая по приоритету: Teacher → ClassTeacher → HeadTeacher → Admin → Parent → Student.
- **Вход по QR (проверено на живом боте 2026-10-17):** страница `/login` создаёт `LoginRequest` (токен в QR-ссылке `https://max.ru/<бот>?start=login_<токен>`, секрет — только в странице, в БД его SHA-256), опрашивает статус раз в 2 с; бот (`BotUpdateHandler`) регистрирует незнакомого по кнопке `request_contact` и спрашивает «Войти на сайт как …? Устройство: Windows, Chrome» кнопками callback; после «Да» страница уходит на `GET /auth/complete?id=&secret=&persistent=` → cookie. QR живёт 3 мин, после подтверждения — 2 мин на завершение; запрос одноразовый. Запрос создаётся в `OnAfterRenderAsync(firstRender)`, а не в `OnInitializedAsync` (иначе пререндер создаст два запроса).
- **Вход из мини-приложения (проверено на живом боте 2026-10-17):** точка входа `wwwroot/max.html` (обычный HTML, не Blazor; библиотека `https://st.max.ru/js/max-web-app.js`) → `WebApp.initData` → `POST /auth/max-webapp` (`MaxWebApp.ValidateInitData`: подпись + `auth_date` не старше 1 часа) → cookie на 30 дней. Незнакомый → кнопка «Поделиться номером» → `WebApp.requestContact()` → `POST /auth/max-webapp/contact` (`MaxWebApp.ValidateContact`: hex(HMAC-SHA256(ключ — токен бота, «authDate=…\nphone=…\nuserId=…»)), номер без «+»).
- **Тестовый стенд (2026-10-24, вместо Dev Tunnel):** https://erudit.23mx.ru → существующий домашний nginx (обратный прокси, HTTPS; шаблон блока — `deploy/nginx-erudit.conf`, обязательно заголовки WebSocket для SignalR) → LXC-контейнер на Proxmox (Ubuntu 22.04, 1 ядро, 1 ГБ; .NET 10 из `ppa:dotnet/backports` — в Ubuntu 22.04 только .NET 8), служба systemd `erudit` (`deploy/erudit.service`, пользователь `erudit`, порт 5000, `ASPNETCORE_ENVIRONMENT=Demo`). Секреты — `/etc/erudit/erudit.env` (`ConnectionStrings__Erudit`, `Max__BotToken`, `Dev__MyPhone`/`Dev__Phones__...`). База `erudit_demo` на том же PostgreSQL (ICU `ru-RU`). Окружение `Demo` (`appsettings.Demo.json`): тестовые данные и номера `Dev:*` как в Development, `MigrateOnStartup` — схема обновляется при запуске, `/dev/login` закрыт (только Development). `UseForwardedHeaders` доверяет любому прокси (порт 5000 — только домашняя сеть). Публикация — `deploy/deploy.ps1` (`dotnet publish -r linux-x64`, архив по scp, папка `/opt/erudit/releases/<дата-время>`, ссылка `/opt/erudit/app`, хранятся 5 версий; `-Setup` — первичная настройка `deploy/setup-server.sh`). SSH: имя `erudit-demo` в `~/.ssh/config`, ключ `~/.ssh/erudit_demo` (вход root по ключу); внутренний IP контейнера в git не пишем. Docker не используем.
- **Прокси nginx** — отдельный контейнер (SSH-имя `erudit-proxy`, ключ тот же; на нём и другие сайты семьи — трогать только своё). Блок — `/etc/nginx/sites-available/erudit.conf` + ссылка в `sites-enabled` (без ссылки запросы уходят в `_default` → переадресация на чужой домен). `map $connection_upgrade` уже объявлен в другом сайте (`ha`) — второй раз нельзя. Сертификат — certbot (`authenticator = nginx`). 2026-10-24: временные папки `/var/lib/nginx/*` принадлежали root → большие ответы (MudBlazor.css 600 КБ) обрывались `ERR_HTTP2_PROTOCOL_ERROR`; исправлено `chown -R www-data`.
- **Сертификат MAX:** API MAX выдан **Russian Trusted Root CA** (Минцифры), его нет в стандартных списках Windows/Linux. Доверяем ему **только в HttpClient для MAX** (`Max/MaxCertificateTrust.cs`, файл `Max/russian_trusted_root_ca.pem` — встроенный ресурс, скачан с gu-st.ru 2026-10-24, проверен по цепочке MAX, SHA-256 `D2:6D:2D:02:...:8E:CF:31`, до 27.02.2032). Систему не меняем.
- `MaxLongPollingService`: бот недоступен при старте → ошибка в журнал и повтор раз в минуту (раньше исключение останавливало весь сайт).
- `deploy.ps1` сохранён в UTF-8 **с BOM** (иначе Windows PowerShell 5.1 читает его в ANSI); скрипты на сервер передаются файлами через scp, не конвейером (PowerShell добавляет BOM/CRLF).
- **Стенд проверен на живом телефоне 2026-10-24:** вход по QR и мини-приложение (`https://erudit.23mx.ru/max.html` в настройках основного бота) работают.
- **Два бота:** основной `@id231107791231_bot` — на стенде (пока long polling; webhook — позже); тестовый `@id231107791231_1_bot` (создан 2026-10-24) — на компьютере разработчика: токен в User Secrets (`Max:BotToken`), имя — `Max:BotUsername` в `appsettings.Development.json`. Long polling одного бота в двух местах отбирает события. У тестового бота мини-приложение не настраиваем: у компьютера разработчика нет публичного HTTPS, а стенд проверяет `initData` токеном основного бота — мини-приложение проверяем только на стенде.

- Регистрация по номеру (бот и мини-приложение) — общий `PersonRegistration.LinkMaxAccountAsync`.
- Журнал (`audit_log`): `Person/MaxLinked`, `Person/LoginConfirmed`, `Registration/PhoneNotFound` (номер не найден — для администратора).

### Календарь и слоты (этап 4, решено 2026-10-19)
- Шаги: справочник четвертей (готов: `/directories/quarters`, `QuarterRules`) → `LessonService` (готов: `CheckAsync` — даты, ошибки, предупреждения; `CreateAsync(..., warningsConfirmed)`; `GetRepeatEndsAsync` — «до конца четверти / полугодия / года»; тесты `LessonServiceTests`) → сетка учителя на неделю → окно «Новое занятие» → изменение/отмена («только это» / «это и все последующие») → сетка любого учителя для завуча и администратора.
- **Главный экран учителя — неделя**: строки Пн–Пт, столбцы — уроки 0–9 со временем; ← → по неделям, «Сегодня»; нерабочие дни и каникулы подсвечены; клик по пустой клетке → «Новое занятие» с подставленными днём и уроком. Вид «месяц» — после отзывов учителей.
- **Справочник четвертей** (`Quarter`: учебный год, номер 1–4, даты): ведут администратор и завуч; четверти внутри учебного года, не пересекаются и идут по порядку. Нужен для «повторять до конца четверти» и отчётов «за четверть».
- **Повторение**: галочка «Повторять каждую неделю до [дата]»; можно отметить несколько дней недели (Вт + Чт → две серии одним действием); быстрые кнопки «до конца четверти» / «до конца полугодия» / «до конца года» + любая дата.
- **Время**: выбрали урок — начало и длительность из звонков; или «вручную» (начало + длительность).
- **Ученики при создании**: класс → галочки + поиск по фамилии по всей школе; у серии — запись на всю серию (`SeriesEnrollment`); учеников больше, чем мест, — нельзя.
- **Конфликты**: у учителя в это время уже есть занятие (не отменённое) → **запрещено**; кабинет занят другим учителем → **предупреждение**, создаём после подтверждения.
- Серия сама пропускает нерабочие дни; разовое занятие на нерабочий день — предупреждение и подтверждение; каникулы — только подсветка; задним числом — можно; в **закрытом месяце** создавать и менять нельзя.
- **«Это и все последующие»**: серия делится на две (старая заканчивается накануне, новая — с этого занятия с новыми параметрами), записи на серию переносятся; проведённые/отмеченные занятия не трогаем — меняются только будущие запланированные. Уведомления об изменениях — этап 6 (пока — журнал).
- **Права**: учитель — только свои занятия; администратор и завуч — смотрят и **правят** занятия любого учителя. Проверка — и в интерфейсе, и в сервисе.
- Окна учителя из школьного расписания — ждём разрешения школьного IT (автор поговорит); сетку строим так, чтобы уроки можно было добавить серым.

### Как выглядит школьное расписание (образец от автора, 8б класс)
- Стандарт школы: **строки — дни недели (Пн–Пт), столбцы — номера уроков** с временем. Календарь в приложении делаем так же.
- Звонки: 1 8:00–8:40, 2 8:55–9:35, 3 9:50–10:30, 4 10:40–11:20, 5 11:30–12:10, 6 12:20–13:00, 7 13:25–14:05, 8 — время не указано.
- Для 9-х классов и старше есть 9-й урок. Время 8-го и 9-го урока задаёт администратор в нашей программе.
- Начальная школа: звонки со 2-го урока совпадают с общими → отдельное расписание звонков не нужно. Но в начальной школе бывают доп. занятия **до 1-го урока** (около 20 минут, начало примерно в 7:30) → в сетке нужен «0-й урок» (время задаёт администратор) или время вручную. Напоминание в 7:00 остаётся (пользователь может настроить своё время).
- Начальная школа (1–4): у ребёнка часто нет MAX → предусмотреть режим, когда родитель получает все уведомления о ребёнке (не только сводку) и может записать ребёнка / отказаться за него.
- Класс делится на группы («1 группа», «2 группа») — **в нашей программе группы не учитываем**: учитель может записать любого ученика, жёсткой привязки ученик ↔ предмет ↔ учитель нет.
- Постоянные доп. занятия из школьного расписания заводятся у нас как регулярные серии.
- Онлайн доп. занятий не бывает.
- У урока: учитель, предмет, кабинет («Каб.8б», «Каб.Естеств», «Спортзал»), этаж.
- Доп. занятия уже встречаются в расписании (8-й урок, пометка «Доп.», например «8б1 мат», «8аб хим» — для подгруппы или нескольких классов).

### Слоты
- Ёмкость слота задаёт учитель (1 и больше).
- Время — по номеру урока, или вручную.
- Обязательные поля: предмет, кабинет. Необязательные: тема, комментарий (обязательность темы — уточнить у руководителя).
- При создании слота учитель может сразу указать учеников.
- Регулярные (повторяющиеся) слоты нужны. Повторения не попадают на нерабочие дни (по производственному календарю).
- Модель: серия (`Series`, правило повторения) + отдельная запись на каждое занятие (`Lesson`). Отмена, перенос, запись учеников, отметка «проведено» — на уровне `Lesson`.
- Изменение как в Google Календаре: «только это занятие» или «это и все последующие». Затронутым ученикам — уведомление в MAX.
- Учитель может отменить конкретное занятие из серии. Записанные ученики получают уведомление.
- Ручное создание слота на нерабочий день — переспросить учителя, после подтверждения создать.
- Учитель может назначить ученика. Подтверждение от ученика не требуется, но ученик может отказаться (уведомление учителю).
- После занятия учитель отмечает, что оно состоялось. От ученика подтверждения не нужно.

### Уведомления (бот MAX)
- Напоминания ученикам и учителям. Пример текста: «У Вас на 7 уроке (13:20–14:00) дополнительные занятия с Ивановым И.И. из 7Б».
- Уведомления об отмене занятия и об отказе ученика.
- Ученику: накануне (на территории школы телефоны не используются) и в день занятия в 7:00. Кнопка «Не смогу прийти».
- Учителю: за 2 часа и за 15 минут. После занятия — кнопки «Проведено» / «Не состоялось».
- Команды бота: «Мои занятия сегодня», «На неделю».
- Принцип: каждое действие (запись, отказ, отмена, перенос…) порождает событие; что и кому отправить — решают настройки уведомлений пользователя. У каждой роли значения по умолчанию, пользователь может включать/выключать типы и менять время.
- Учителю доступно: уведомление о каждой записи / сводка / утренняя сводка — по выбору в настройках.
- Ученику «накануне» — в 17:00 предыдущего календарного дня (для понедельника — воскресенье 17:00).
- Родителям по умолчанию — еженедельная сводка; в настройках можно выбрать ежедневную и удобное время.
- Схема отправки: мгновенные уведомления (запись, отказ, отмена, перенос) — событие → настройки получателя → очередь → отправка. Всё по времени (напоминания, сводки, неотмеченные занятия) — одна ежеминутная задача Hangfire, которая вычисляет по актуальным данным, что пора отправить. Журнал отправленного с уникальным ключом (пользователь + занятие + тип) — защита от дублей.
- Поздняя запись (время напоминаний уже прошло) — отправить уведомление сразу.
- Неотмеченное занятие: напомнить учителю вечером + список «неотмеченные» на сайте.
- Тихие часы не делаем.
- Фоновые задачи — Hangfire (предварительно).
- Часовой пояс школы UTC+3 (Europe/Moscow). В БД время в UTC, в местное — только при показе.

### MAX: технические факты (из dev.max.ru, проверено 2026-10-16)
- Мини-приложение живёт только внутри бота; работает на iOS, Android, desktop и web-версии MAX (часть API, например хранилища и вибрация, на desktop/web не работает).
- `window.WebApp.initData` содержит `user` (id, имя, фамилия, username, фото), `chat`, `auth_date`, `hash`. Телефона в initData нет.
- Проверка на сервере: `secret = HMAC_SHA256(key="WebAppData", msg=botToken)`, пары `key=value` без `hash` сортируются по ключу и склеиваются через `\n`, `hex(HMAC_SHA256(secret, строка)) == hash`. Свежесть `auth_date` проверяем сами.
- `WebApp.requestContact()` отдаёт телефон пользователя с подписью (`phone`, `authDate`, `hash`), подпись проверяется на сервере тем же способом.
- Токен бота — только на сервере, никогда в git. Ключ в User Secrets: `Max:BotToken`.
- Bot API: `https://platform-api2.max.ru`, заголовок `Authorization: <токен>`. `GET /me`, `GET /updates?timeout=&marker=` (long polling — по документации только для разработки, в рабочей версии webhook `POST /subscriptions`), `POST /messages?user_id=` с телом `{"text": ...}` (не больше 2 сообщений в секунду в один диалог).
- Реальный формат событий (из лога, 2026-10-17):
  - `bot_started`: `chat_id`, `user{user_id, first_name, last_name, name, is_bot}`, `payload` (только если открыли ссылку с `?start=`), `user_locale`, `timestamp` (мс).
  - `message_created`: `message{sender{user_id, first_name, ...}, recipient{chat_type:"dialog", chat_id, user_id}, body{mid, seq, text}, timestamp}`, `user_locale`.
  - `message_callback` (кнопка callback): `callback{callback_id, payload, user{user_id, ...}, timestamp}`, `message` (сообщение с кнопкой). Ответ — `POST /answers?callback_id=` с `{"message": {...}}`: заменяет сообщение, пустой `attachments` убирает кнопки.
  - Контакт (кнопка `request_contact`) приходит как `message_created` с вложением `{"type":"contact","payload":{"vcf_info":"BEGIN:VCARD\r\n...TEL;TYPE=cell:7999...\r\n...","max_info":{"user_id",...},"hash":"<64 hex>"}}`. `hash` = **hex(HMAC-SHA256(ключ: токен бота, сообщение: vcf_info))** — проверено на живом боте.
  - Кнопки: `{"type":"callback","text","payload"}`, `{"type":"request_contact","text"}`, вложение `{"type":"inline_keyboard","payload":{"buttons":[[...]]}}`.
- Код: `Erudit.Infrastructure/Max/` — `IMaxBotClient`/`MaxBotClient` (HTTP-клиент), `MaxMessage`/`MaxButton`, `MaxContact` (проверка контакта), `BotUpdateHandler` (логика бота), `MaxLongPollingService` (фоновая служба, включается `Max:UseLongPolling=true` в `appsettings.Development.json`; полный JSON событий пишет на уровне Debug — в нём персональные данные). Имя бота для ссылок — `Max:BotUsername` в `appsettings.json`.

### Посещаемость и учёт времени
- Учитель отмечает занятие проведённым и посещаемость каждого записанного ученика (присутствовал / отсутствовал).
- Длительность — по плану, учитель может поправить фактическую при отметке.
- Групповое занятие 1 час с 5 учениками: у учителя 1 час, у каждого ученика 1 час.
- **В отчётах время считается в академических часах по 40 минут.** В БД храним минуты; ак. ч. = минуты / 40 вычисляем в отчёте (занятие 20 мин = 0,5 ак. ч., 60 мин = 1,5 ак. ч.). Округляем **только итог** (отдельные занятия не округляем); точность итога — уточнить у руководителя.
- Доп. занятия учитываются для оплаты/нагрузки учителей → нужно «закрытие периода» (после закрытия прошлые занятия не меняются).

### Отчёты
- Экран + выгрузка в Excel (ClosedXML). PDF пока не нужен (если понадобится — например, Gotenberg).
- Фильтры: произвольный период, месяц, четверть, учебный год; предмет, класс, ученик.
- Учитель: мои занятия за период, разбивка по ученикам и классам, часы — отдельно индивидуальные и групповые.
- Классный руководитель: кто из моих учеников куда ходит и сколько; посещаемость.
- Завуч / админ: сводка по всем учителям (занятия, часы); проверочный отчёт по всем ученикам (кто в каком классе, зарегистрирован ли в MAX, привязаны ли родители) — для проверки корректности импорта.
