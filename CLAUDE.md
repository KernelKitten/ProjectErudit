# Project Erudit

Школьный проект: приложение для записи на дополнительные занятия. Учитель отмечает в календаре свободные слоты, ученики на них записываются (или учитель назначает ученика сам).

## Принятые решения

### Стек (предварительно, окончательно — после разговора со школьным IT)
- Blazor (Server или смешанный режим — обсуждается), PostgreSQL, C#, Visual Studio.
- Авторизация и уведомления через мессенджер MAX (бизнес-аккаунт уже есть): мини-приложение + бот.

### Масштаб
- До 50 учителей и до 1000 учеников, одна школа.
- Приложение для средней и старшей школы (5–11 классы). Пятидневка.
- Учителя работают в основном с ноутбуков; ученики, скорее всего, с телефонов (мобильный вид — проверять на практике).

### Роли
- Учитель (основная роль: изначально приложение для учителей; ученики — дополнение).
- Ученик.
- Администратор.
- Завуч / руководитель — видит отчёты по всем.
- Классный руководитель — может вести несколько классов, видит всё о своих учениках. У него есть телефоны детей и родителей.
- Родитель — желательно. Привязка «родитель ↔ ученик» — через одноразовый код, который выдаёт классный руководитель (ученик в подтверждении не участвует). Если IT даст связи из школьной базы — импорт.
- У одного человека может быть несколько ролей.

### Школьное расписание (rasp.erudit23.ru) — возможный источник данных
- Сайт гимназии «Эрудит» сам грузит данные из JSON (неофициальный API, без документации — нужно разрешение школьного IT, admin@erudit23.ru):
  - `https://rasp.erudit23.ru/json/readJsonRaspForAll.php` (~850 КБ): `raspByKlass`, `raspByTeacher`, `raspByClassrooms`, `hoursByTeacher`, `teachersArray`, `teachersFullArray`, `classroomsArray`, `klassTeachers` (класс → ФИО классного руководителя), `subjectsLong`.
  - `https://rasp.erudit23.ru/json/readJsonRaspByKlass.php?ts=<метка>` — с параметром `ts` отвечает `{"cached":true}`, если расписание не менялось (удобно для периодической проверки).
  - Запись урока: `klassStr`, `dayN` (0 = Пн), `urokN` (0 = 1-й урок), `subjectStr`, `groupStr`, `teacherStr` (Фамилия И.О.), `classroomStr`; в `raspByTeacher` ещё `ringStart`/`ringEnd`.
- Применение: импорт учителей, классов, классных руководителей, предметов, кабинетов, звонков; предупреждение о конфликтах (у класса урок, кабинет занят). Учеников там нет.
- Формат может измениться без предупреждения → отдельный адаптер в `Infrastructure`, ошибки разбора не должны ломать приложение.

### Регистрация и пользователи
- Основной способ: пользователь делится телефоном через `requestContact()` в MAX, сервер ищет номер в загруженных списках и привязывает аккаунт MAX к ученику / родителю / учителю. Одноразовый код от классного руководителя — запасной вариант.
- Списки загружаются из Excel по шаблону (шаблон можно скачать в приложении). Всю школу загружает администратор / завуч, свой класс — классный руководитель.
- Классный руководитель может править карточки своих учеников вручную.
- Ученик без MAX: классный руководитель добавляет его в список класса, учитель записывает на занятие вручную; уведомлений он не получает.

- Учителя/завуч/админ работают в основном в браузере на ноутбуке, ученики/родители — в мини-приложении. Страницы адаптивные.

### Справочники
- Классы (7А, 9Б), предметы, связь учитель ↔ предметы ↔ классы.
- Расписание звонков (номера уроков и их время).

### Как выглядит школьное расписание (образец от автора, 8б класс)
- Стандарт школы: **строки — дни недели (Пн–Пт), столбцы — номера уроков** с временем. Календарь в приложении делаем так же.
- Звонки: 1 8:00–8:40, 2 8:55–9:35, 3 9:50–10:30, 4 10:40–11:20, 5 11:30–12:10, 6 12:20–13:00, 7 13:25–14:05, 8 — время не указано.
- Для 9-х классов и старше есть 9-й урок. Время 8-го и 9-го урока задаёт администратор в нашей программе.
- Класс делится на группы («1 группа», «2 группа») — **в нашей программе группы не учитываем**: учитель может записать любого ученика, жёсткой привязки ученик ↔ предмет ↔ учитель нет.
- Постоянные доп. занятия из школьного расписания заводятся у нас как регулярные серии.
- Онлайн доп. занятий не бывает.
- У урока: учитель, предмет, кабинет («Каб.8б», «Каб.Естеств», «Спортзал»), этаж.
- Доп. занятия уже встречаются в расписании (8-й урок, пометка «Доп.», например «8б1 мат», «8аб хим» — для подгруппы или нескольких классов).

### Слоты
- Ёмкость слота задаёт учитель (1 и больше).
- Время — по номеру урока, или вручную.
- Обязательные поля: предмет, кабинет. Необязательные: тема, комментарий (обязательность темы — уточнить у руководителя).
- При создании слота учитель может сразу указать учеников.
- Регулярные (повторяющиеся) слоты нужны. Повторения не попадают на нерабочие дни (по производственному календарю).
- Модель: серия (`Series`, правило повторения) + отдельная запись на каждое занятие (`Lesson`). Отмена, перенос, запись учеников, отметка «проведено» — на уровне `Lesson`.
- Изменение как в Google Календаре: «только это занятие» или «это и все последующие». Затронутым ученикам — уведомление в MAX.
- Учитель может отменить конкретное занятие из серии. Записанные ученики получают уведомление.
- Ручное создание слота на нерабочий день — переспросить учителя, после подтверждения создать.
- Учитель может назначить ученика. Подтверждение от ученика не требуется, но ученик может отказаться (уведомление учителю).
- После занятия учитель отмечает, что оно состоялось. От ученика подтверждения не нужно.

### Календарь
- Производственный календарь: https://github.com/Duff072/holidays-calendar (доработанный форк d10xa/holidays-calendar, обновляется сам), файл `json/calendar.json`. Массивы дат: `holidays` (выходные + праздники), `preholidays` (сокращённые дни), `nowork` (нерабочие дни по указу).
- Загрузка — гибрид: приложение раз в неделю тянет файл с GitHub в БД; администратор может загрузить файл вручную и исправить отдельные дни.
- Праздники отдельно не показываем — достаточно признака «рабочий / нерабочий день». Сокращённые дни на звонки не влияют.
- Расписание звонков одно на всю школу, вводит администратор / завуч.
- Каникулы вводит администратор / завуч, они только подсвечиваются (занятия на каникулах разрешены).

### Уведомления (бот MAX)
- Напоминания ученикам и учителям. Пример текста: «У Вас на 7 уроке (13:20–14:00) дополнительные занятия с Ивановым И.И. из 7Б».
- Уведомления об отмене занятия и об отказе ученика.
- Ученику: накануне (на территории школы телефоны не используются) и в день занятия в 7:00. Кнопка «Не смогу прийти».
- Учителю: за 2 часа и за 15 минут. После занятия — кнопки «Проведено» / «Не состоялось».
- Команды бота: «Мои занятия сегодня», «На неделю».
- Принцип: каждое действие (запись, отказ, отмена, перенос…) порождает событие; что и кому отправить — решают настройки уведомлений пользователя. У каждой роли значения по умолчанию, пользователь может включать/выключать типы и менять время.
- Учителю доступно: уведомление о каждой записи / сводка / утренняя сводка — по выбору в настройках.
- Ученику «накануне» — в 17:00 предыдущего календарного дня (для понедельника — воскресенье 17:00).
- Родителям по умолчанию — еженедельная сводка; в настройках можно выбрать ежедневную и удобное время.
- Схема отправки: мгновенные уведомления (запись, отказ, отмена, перенос) — событие → настройки получателя → очередь → отправка. Всё по времени (напоминания, сводки, неотмеченные занятия) — одна ежеминутная задача Hangfire, которая вычисляет по актуальным данным, что пора отправить. Журнал отправленного с уникальным ключом (пользователь + занятие + тип) — защита от дублей.
- Поздняя запись (время напоминаний уже прошло) — отправить уведомление сразу.
- Неотмеченное занятие: напомнить учителю вечером + список «неотмеченные» на сайте.
- Тихие часы не делаем.
- Фоновые задачи — Hangfire (предварительно).
- Часовой пояс школы UTC+3 (Europe/Moscow). В БД время в UTC, в местное — только при показе.

### MAX: технические факты (из dev.max.ru, проверено 2026-10-16)
- Мини-приложение живёт только внутри бота; работает на iOS, Android, desktop и web-версии MAX (часть API, например хранилища и вибрация, на desktop/web не работает).
- `window.WebApp.initData` содержит `user` (id, имя, фамилия, username, фото), `chat`, `auth_date`, `hash`. Телефона в initData нет.
- Проверка на сервере: `secret = HMAC_SHA256(key="WebAppData", msg=botToken)`, пары `key=value` без `hash` сортируются по ключу и склеиваются через `\n`, `hex(HMAC_SHA256(secret, строка)) == hash`. Свежесть `auth_date` проверяем сами.
- `WebApp.requestContact()` отдаёт телефон пользователя с подписью (`phone`, `authDate`, `hash`), подпись проверяется на сервере тем же способом.
- Токен бота — только на сервере, никогда в git.

### Посещаемость и учёт времени
- Учитель отмечает занятие проведённым и посещаемость каждого записанного ученика (присутствовал / отсутствовал).
- Длительность — по плану, учитель может поправить фактическую при отметке.
- Групповое занятие 1 час с 5 учениками: у учителя 1 час, у каждого ученика 1 час.
- Доп. занятия учитываются для оплаты/нагрузки учителей → нужно «закрытие периода» (после закрытия прошлые занятия не меняются).

### Отчёты
- Экран + выгрузка в Excel (ClosedXML). PDF пока не нужен (если понадобится — например, Gotenberg).
- Фильтры: произвольный период, месяц, четверть, учебный год; предмет, класс, ученик.
- Учитель: мои занятия за период, разбивка по ученикам и классам, часы — отдельно индивидуальные и групповые.
- Классный руководитель: кто из моих учеников куда ходит и сколько; посещаемость.
- Завуч / админ: сводка по всем учителям (занятия, часы); проверочный отчёт по всем ученикам (кто в каком классе, зарегистрирован ли в MAX, привязаны ли родители) — для проверки корректности импорта.
